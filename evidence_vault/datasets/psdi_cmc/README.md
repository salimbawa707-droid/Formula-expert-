## Inventory and initial structural audit

- `NIST_Table_of_Critical_Micelle_Concentration_Values.csv`: 4,990 data rows; fields include compound number, source CMC text, normalized value/unit slots, temperature, method, author/reference codes, and evaluation metadata.
- `CMC_Compounds.csv`: 719 compound rows with name, IUPAC, SMILES, molecular weights, and a method/provenance field.
- In the 4,990-row measurement file, 4,559 rows have numeric `CMC Value 1`; the first-unit field uses `M`, `D`, `W`, `P`, `N`, or blank. The original NBS NSRDS 36 concentration-unit legend maps `M` = molar, `D` = wt/vol %, `W` = molal, `P` = wt %, `N` = normal, `S` = mol/kg, and `R` = varied. The second value/unit fields contain 474 populated rows; the third has four populated rows. `R` denotes varying units, so it is not convertible. The code inventory is in [`structural-audit.json`](./structural-audit.json). This legend decoding does not make records homogeneous: preserve original values and codes, and do not convert units without checking record context and source conditions.
- The source also has free-text `CMC` cells and reference codes. Preserve all fields; do not parse date-like/reference codes as concentrations or collapse multiple measurement methods/temperatures into one value.
- All 719 compound numbers in the measurement table have matching keys in the 719-row compound table, but this is only a key-set match, not validation of names or structures. The compound table's identity methods are 530 `LLM initial name and weight`, 58 `Found by mass lookup`, 13 `LLM retried name and weight`, 115 `Unknown`, and 3 `PubChem name`. One visible candidate identity inconsistency is “SODIUM OCTYL 1 SULFATE” paired with IUPAC “sodium;2-ethylhexyl sulfate” and a branched structure. Treat identity matching as unresolved pending source-reference curation.
- The unit legend is in the [original NIST/NBS NSRDS 36 publication](https://nvlpubs.nist.gov/nistpubs/Legacy/NSRDS/nbsnsrds36.pdf) (concentration-units legend, p. 222).

## Structural audit\n\nA structural inventory is archived in [`structural-audit.json`](./structural-audit.json). It records source blob IDs, row and column completeness counts, observed unit-code frequencies, and compound-key coverage. The `Evaluation` field contains mostly `L` (4,020), `R` (191), `X` (63), numeric values, and a small number of irregular strings; this audit records frequencies but does not infer their meanings. `Qual. Mat. Meth.`, author codes, reference codes, and additive codes also remain unexpanded. The audit is not a row-by-row transcription check against the 1971 NIST/NBS volume.\n\n## Use gate

This is an openly licensed literature-derived data collection, not a new app laboratory campaign. Archive only for provenance-preserving research. Do not load values into ingredient master data, calibrate a model, or claim engine validation until individual compound identity, unit code, source reference, method, temperature, and record quality are resolved. The dataset's AI-assisted extraction history is documented on the [PSDI resource page](https://resources.psdi.ac.uk/data/a7c82670-d2e2-46c6-920a-74294289aa34).
